# Вибір предметної області

## Status

Accepted

## Context and Problem Statement

Перша модель зберігала лише поточний статус заявки, через що неможливо було побачити і опрацювати історію її розгляду

## Decision Drivers

Збереження історії, можливість відстеження змін, уникнення дублювання даних

## Considered Options

Один атрибут status (втрачається історія переходів); атрибут status та окрема історія (можлива неузгодженість даних); лише окрема сутність історії (потрібна додаткова операція для визначення поточного статусу)

## Decision Outcome

Обрано `SWAP_STATUS_HISTORY` із видаленням атрибута status із `SWAP_REQUEST`

## Consequences

Тепер історія зберігається повністю без дублювання поточного статусу, проте для його визначення потрібно знаходити останній запис історії
